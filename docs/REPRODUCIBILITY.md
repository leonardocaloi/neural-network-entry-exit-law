# Reproducibility guide

Three levels are available, from seconds to hours. Everything runs on CPU;
no GPU is used anywhere in the project.

| Level | What it does | Time on the release machine |
|---|---|---|
| Quick checks | Verifies the archived evidence and runs small independent integrations | under 1 minute |
| Analysis only | Recomputes every table of the two confirmatories from the archived per-run records | seconds |
| Full regeneration | Reruns the lemma scripts, the sweep and the two training campaigns | minutes to hours (see §4) |

Commands assume a POSIX shell at the repository root unless a `cd` is shown.

## 1. Environment

Python 3.14 was used historically and for the release checks (3.14.6). The
analysis and verification environment is pinned:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt          # numpy 2.4.2, scipy 1.16.3, sympy 1.14.0, matplotlib 3.10.8
```

The MLP and transformer engines (`motor_4a3.py`, `motor_taxa.py`,
`motor_e5_conf.py`, `harness_mlp.py`) additionally need PyTorch. The exploratory
Adam toy script `e7_adam.py` uses NumPy. The release checks
used torch 2.13.0. A CPU-only wheel is sufficient and much smaller than the
default PyPI wheel, which bundles CUDA libraries on Linux:

```sh
pip install torch==2.13.0 --index-url https://download.pytorch.org/whl/cpu
# or, accepting the large default wheel:
pip install -r requirements-experiments.txt
```

`uv` works as a drop-in replacement (`uv venv --python 3.14 .venv`,
`uv pip install -r requirements.txt`).

Historical environment of the July 2026 campaigns, as recorded in the
manuscript: Intel Core i9-9900K, single-threaded runs, four concurrent
workers, Python 3.14, NumPy 2.4; the PyTorch version was not recorded. No
dependency lockfile from that time exists. The release checks of October 2026
ran on the same machine.

## 2. Quick checks (seconds)

```sh
python verification/smoke.py
```

Checks that all 1,800 archived per-run files match their SHA256 manifests
(`results-4a3/manifest-4a3.json`, `results-e5/manifest-e5.json`,
`etapa4-mlp-populacao/results/manifest.json`) and that both configuration
files match the hashes stored in the manifests. It then loads the frozen
analysis modules (`analise_4a3.py`, `analise_e5.py`) and asserts the complete
grids, the main denominators quoted in the manuscript, the negative controls
and the Clopper–Pearson intervals, and recomputes the 600-draw sweep summary
(57 retained, median error 2.68%). About 5 s and 140 MB of RAM. Nothing is
written.

```sh
python verification/smoke.py --engines
```

Adds the PyTorch checks: bit-exact parity of the two MLP engines on five short
cases, determinism of the transformer engine on a 200-step run, and the
frozen-ReLU null (zero own-parameter movement). About 10 s and 0.9 GB of RAM.

```sh
python verification/check_entry_exit.py
# Optional: save a new report outside the archived evidence.
python verification/check_entry_exit.py --output build/entry-exit-checks.json
```

Independent of the historical Euler integrator. Verifies the scalar
quadrature identity symbolically (SymPy), the Jacobian-rank counterexample,
and the entry–exit coefficient on three archived instances (m = 4, 8, 16)
with SciPy's DOP853 at rtol 2e-12 and event interpolation, for β from 1e4 to
3e5. About 3 s. `docs/verification/entry-exit-checks.json` is the report
produced during the release review.

## 3. Analysis only (seconds)

The frozen analyses read the archived records and print the report that the
manuscript tables were transcribed from. They write nothing.

```sh
python 05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/analise_4a3.py
python 05-experimentos/etapa5-transformer/analise_e5.py
```

Both accept `--resultados <dir>` to point at a regenerated directory. They
took 0.3 s and 1.1 s on the release machine.

Figures are regenerated by scripts next to the manuscript
(`06-notas/paper/figuras_paper.py`, `figura_grade_e5.py`,
`figura_barreira_gelu.py`, `figura_trajetoria3d.py`) and by
`06-notas/t2-prova/figuras_draft.py` (Figures 1 and 2). `figura_barreira_gelu.py`
uses no experimental data and was rerun for the release.

## 4. Full regeneration

### 4.1 Lemma verifications (seconds to minutes each)

```sh
cd 06-notas/t2-prova
python passo0_verificacao.py     # ... through passo6_verificacao.py
python prova_L1_verificacao.py   # ... through prova_L6_verificacao.py
```

Each script prints `[OK]` lines and a final verdict. On the release machine
`passo0_verificacao.py` took 0.5 s and `prova_L1_verificacao.py` 44 s; the
other scripts were not timed for the release. The forcing-theorem numerics are
in `05-experimentos/t2-n-neuronios/` (`verifica_forcing.py`, `beta.py`,
`parecer14.py`, `parecer15_o5.py`, `parecer15_o5b.py`, wrapped by
`gera_artefatos.py`); the manuscript reports about 1 hour wall-clock for the
whole set, single-threaded.

### 4.2 Two-neuron sweep (about 12 minutes)

```sh
cd 05-experimentos/t2-sweep-instancias
python sweep_instancias.py       # 600 draws, beta = 1e4, Euler dt = 1e-5
```

The historical run took 11.8 min (`sweep_run.log`). The script overwrites
`sweep_instancias.jsonl`; copy the archived file first if you want to compare.

### 4.3 Training campaigns (hours)

Both runners skip existing result files. Merely cloning the repository does
not rerun the campaigns, because their archived outputs are included. Use a
separate reproduction copy and move its result directories aside first; retain
them for comparison. The commands below take hours and are **not** quick checks.

With dependencies installed and the environment activated, from the original
checkout's root:

```sh
git clone --branch v0.1.1 https://github.com/leonardocaloi/neural-network-entry-exit-law.git ../entry-exit-reproduction
cd ../entry-exit-reproduction
export OMP_NUM_THREADS=1

# Preserve the archived MLP records in this reproduction copy.
mv 05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/results-4a3 05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/results-4a3-archived
python 05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/run_4a3.py --workers 4
python 05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/analise_4a3.py

# Preserve the archived transformer records in this reproduction copy.
mv 05-experimentos/etapa5-transformer/results-e5 05-experimentos/etapa5-transformer/results-e5-archived
python 05-experimentos/etapa5-transformer/run_e5.py --workers 4
python 05-experimentos/etapa5-transformer/analise_e5.py
```

Historical times with four single-threaded CPU workers were 4.9 hours for
400 MLP runs and 13.9 hours for 800 transformer runs. The release review did
not rerun these campaigns or independently profile peak memory for every run.

The runners also provide `--smoke`, writing separate ignored smoke directories.
The MLP runner uses two shorter 20,000-step runs; the transformer runner still
uses two full 200,000-step runs. For a much smaller engine check, use
`python verification/smoke.py --engines` instead. Transformer `--estimativa`
times two full runs and is not a lightweight metadata query.

### 4.4 Comparing a regenerated run with its archive

Regenerated `.jsonl.gz` files will not be byte-identical to the archived
ones: each record stores its elapsed time (`segundos`) and gzip stores
metadata. Library and platform changes may also change floating-point
trajectories. Compare numerical content instead:

```sh
python verification/compare_runs.py path/to/archived.jsonl.gz path/to/regenerated.jsonl.gz --rtol 1e-6 --atol 1e-8
```

Counts, flags, strings and integers must match exactly; floats are compared
with the given tolerances; only the root-level `segundos` field is ignored.

## 5. Building the manuscript

```sh
cd 06-notas/paper
pdflatex paper-v4.tex && pdflatex paper-v4.tex && pdflatex paper-v4.tex
```

Requires a TeX Live installation with `amsmath`, `geometry`, `graphicx`,
`url`, `booktabs`, `microtype`, `aliascnt`, `algorithm`, `algorithmic`,
`hyperref` and `cleveref`. The bibliography is inline, so no BibTeX step is
needed. The release build produced 66 pages with no errors.

## 6. What is archived, exactly

- `05-experimentos/etapa4-mlp-populacao/pilotos-4a2/pressao/taxa/results-4a3/`:
  400 run summaries of the MLP confirmatory (one `.jsonl.gz` per run) and the
  SHA256 manifest `manifest-4a3.json`, which also stores the hash of
  `config_4a3.json`.
- `05-experimentos/etapa5-transformer/results-e5/`: 800 run summaries of the
  transformer confirmatory and `manifest-e5.json` (with the hash of
  `config_e5.json`).
- `05-experimentos/etapa4-mlp-populacao/results/`: the 600 runs of the
  discarded `etapa-4a` instrument (a negative result, kept as evidence).
- Pilot records: `pilotos-4a2/results-piloto/`, `etapa5-transformer/results-piloto/`
  and `results-taxa/`.
- `05-experimentos/t2-sweep-instancias/sweep_instancias.jsonl`: the 600-draw
  sweep; `05-experimentos/t2-n-neuronios/*.jsonl`: forcing-theorem numerics.

The archived run files are run and episode summaries (per-unit events, areas,
counters and loss summaries), not full per-step trajectories.
